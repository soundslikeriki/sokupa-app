# 保留した結果と受付失敗後の復元

独立レビュー72b01ddのP2「別端末で確認済み・通知acceptedになると、この端末で後回しにした結果を開けない」と、P3「新規受付503後に旧結果の復元選択が止まる」を修正。本番は未変更。

## この端末で後回しにした結果

`client_result_seen_at`はユーザー共通の確認情報で、端末ごとの受領証明にはしない。通知完了によるlastJobId削除は、この端末の保存済み下書きが同じjob IDを持つ場合に限定した。別端末のseenだけでは消さない。端末の明示ポインターは、別の下書きがある場合も復元候補として取得し、上書き前に切替方法を選ぶ。

「今の下書きを続ける」は、別の解析結果をjob IDごとの独立した復元用下書きへ保存し、readbackが一致してから後回し表示にする。現在の編集や発注下書き、サーバーのseenには触れない。同じjobの既存保管は検証して再利用し、容量不足・不正な既存値・readback失敗を成功扱いしない。

保管した結果は「退避した下書き」から復元・書き出せる。通信不能でも保管した結果を開ける。復元前に現在の編集は従来どおり退避する。結果の保管には現行の発注下書きを誤って関連付けない。端末内データの消去・端末紛失を超える保存保証ではない。

## サーバーの保存済み解析を開く

「保存済みの解析結果を探す」を追加。別端末で確認済み・LINE受付済みの完了結果も一覧から選べる。端末への保存が失敗し、新規解析でlastJobIdが更新された場合もこの経路を使う。履歴取得エラーは再試行でき、現在の編集は変更しない。選択した結果は本人専用GETから取得し、現在の下書きが異なる場合は確認付き切替へ進む。進行中の解析を履歴選択で置換しない。

既存の署名認証と本人フィルターを用い、完了ジョブのID・現場名・作成日時・通知状態だけを1ページ20件返す。結果本体は選択した本人ジョブだけを取得する。次ページのanchorも本人・doneを検証し、created_atとidの組でページ送りする。同時刻の行もページ境界から落とさず、本人以外のanchorは404、不正IDは400、DB失敗は503、未認証は401。client_result_seen_atと通知状態は履歴の除外条件にしない。履歴閲覧だけではseen更新・解析再実行・LINE送信をしない。

新規解析前にも保留結果の端末保管を試みる。容量不足の場合はサーバー履歴を案内し、新しい解析を止めない。既存DB行を削除する処理は追加しない。サーバーデータの削除や全損からの復旧は本番バックアップの範囲であり、この履歴では保証しない。

## 新規受付失敗

アップロード／受付を始める時点の解析選択を保持する。新規受付に失敗し、その間に利用者が別の結果を明示選択していなければ元の選択を戻し、復元の世代を更新して状態・結果取得を再開する。初期復元の応答を新規受付中に破棄した場合も一覧から再確認する。再読込を必須にしない。成功した新規受付を古い応答で置換しない保護は維持する。
